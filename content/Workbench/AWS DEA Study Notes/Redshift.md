| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Command       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `COPY`        | Load large volume of data in parallel directly from Amazon S3 into the compute nodes  <br>  <br>Never use individual `INSERT` statements for large volumes; `COPY` is significantly faster and more efficient                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `INSERT`      |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `UNLOAD`      | Transfers the results of a leader-node query to S3  <br>  <br>It allows you to export query results in parallel, often used to move processed data back into a data lake                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `VACUUM`      | A family of commands that reclaim disk space from deleted or updated rows, rebuilding indexes, and reorganizing tables.<br><br>**`VACUUM FULL`** – Reclaims disk space, rebuilds indexes, and re-sorts all rows in the table. This is the default `VACUUM` operation in Redshift.<br><br>**`VACUUM DELETE ONLY`** – Only reclaims disk space occupied by deleted rows without re-sorting data. This is faster than `VACUUM FULL` but does not optimize query performance. Used when interleaved sort keys are skewed.<br><br>**`VACUUM SORT ONLY`** – This command performs a sort-only operation on the table without reclaiming disk space. It is useful when rows are unsorted, but space is not an issue. |

### **Distribution style**

| Style | Description                                                   | Use Case                                                                                                                                                                                       |     |
| ----- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| KEY   | Distributes rows based on a column’s values to optimize joins | Used when joining large tables on a common key such as `customer_id`. This ensures that data is evenly distributed across nodes based on the specified key.                                    |     |
| EVEN  | Data is spread evenly across all nodes                        | This is the default distribution style for large tables to ensure an even spread of data and better query performance. It’s useful when there is no clear column for co-locating related data. |     |
| ALL   | Copies entire table to all nodes                              | For small "dimension" or lookup tables, always choose **DISTSTYLE ALL**. This eliminates data movement when joining with large "fact" tables.                                                  |     |
| AUTO  | Redshift chooses the style for a table based on table size    |                                                                                                                                                                                                |     |

### **Sort keys**

| Sort key    | Use case                                                                                                   | Notes                                                                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Single      | Ideal for queries that filter on one specific column, like `order_date`.                                   |                                                                                                                                                          |
| Compound    | Useful when queries filter on multiple columns in a consistent order. Best for queries with range filters. |                                                                                                                                                          |
| Interleaved | Best for queries that filter across multiple columns with different patterns.                              | `VACUUM REINDEX` Removes and rebuilds **interleaved** sort keys in Redshift tables to improve query performance and ensure consistent data distribution. |

### Fault Tolerance



> 🔥 Disaster Recovery: Enable **automated snapshots** and configure **cross-region snapshot copy** for recovery from regional failures. For mission-critical clusters, maintain a **warm standby cluster** or automate **on-demand cluster restoration** via snapshots and CloudFormation.

| **Capability**                         | **This Enables**                                                                         |
| -------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Automated backups and snapshots**    | Restores clusters to any point in time. Snapshots stored in S3 (can be cross-region).    |
| **Cluster replication (cross-region)** | Disaster recovery and business continuity; restore to new region during regional outage. |
| **Leader/Compute node separation**     | Query planner isolation prevents full-cluster failure from single node loss.             |
| **Data replication within cluster**    | Blocks stored redundantly within nodes for high durability.                              |
| **RA3 managed storage on S3**          | Protects against disk failure; automatic rehydration of lost data.                       |
| **Elastic resize / node replacement**  | Allows resizing or recovery without data loss.                                           |

## Performance Optimization

### Stored procedure optimization

- Use temporary tables
    

- Minimize cursor usage
    
    - Use set-based operations instead to process data in bulk
        

- Use parameters (input arguments)
    

- Use `EXCEPT` blocks for error handling
    
    - `WHEN OTHERS`
        
    
    - `RAISE NOTICE`
        
    
    - `ROLLBACK`
        

### File compression

Compression helps reduce the amount of storage required for your data and can improve query performance by minimizing the amount of data that needs to be read from disk.

|   |   |   |
|---|---|---|
|Format|Suited for||
|AZ64|Numeric and date/time columns||
|ZSTD|Mixed data types|high compression efficiency with fast decompression, balancing both speed and storage savings.  <br>  <br>Also supported in Athena|
|LZO|strings with low cardinality, like status codes, categories or repetitive values|Suited for logs, where strings may repeat often or have low cardinality|
